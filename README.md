# Twimark

X・note・Qiitaの投稿と記事を、カテゴリ・サブカテゴリ付きのカードで見るブックマークツール。一覧は Cloudflare Workers の画面（`https://twimark.ho-service.workers.dev`）で開き、追加は一覧の画面の「＋」（URL を貼る）、Chrome/Edge の拡張機能、iPhone アプリ（Expo Go）から行う。一覧の画面とアプリは同じ機能を持つ。

ブックマークは Cloudflare D1 に置き、ログインした利用者だけが、それぞれ自分の分を読み書きできる。利用者を増やすときは、管理者（最初に登録した人）が招待リンクを作って渡す。ログインは ID とパスワードで、パスキーを足すとパスキーを先に求める。

## はじめに（一度だけ）

### 1. 登録する

公開した画面（`https://twimark.ho-service.workers.dev`）を開くと、登録の画面が出る。ID とパスワード（10文字以上）を入れて登録する。最初の1人が管理者になり、登録は閉じる。ほかの人は、管理者が「設定」の「招待」で作った招待リンク（1回きり、3日で切れる）からだけ登録できる。ブックマークは人ごとに別で、ほかの人のものは見えない。

「設定」の「ログインの履歴」には、自分の ID へのログインの成功と失敗（30日分、日時・方法・Web かアプリか・IP・国・端末）が出る。

パスキーを使うときは、「設定」の「パスキーを追加」で足す。次からは、ID を入れて「次へ」を押すとパスキーを求められる。パスキーが使えないときは「パスワードでログイン」を押す。

### 2. 拡張機能を入れる

```bash
node scripts/build.mjs
```

Chromeは `chrome://extensions`、Edgeは `edge://extensions` を開き、デベロッパーモードをオンにして「パッケージ化されていない拡張機能を読み込む」で `build/extension` を選ぶ。

一覧の画面の「設定」の「拡張のトークンを発行」で名前を入れて「発行」を押し、出てきた値を拡張機能の「オプション」（設定）に入れて「接続を確かめる」。値は発行したときに一度だけ出る。要らなくなったら、一覧の画面の「設定」で取り消す。

コードを変えたら `node scripts/build.mjs` をやり直し、拡張機能のページで再読み込みする。開いていたX・note・Qiitaのタブも再読み込みする。

## 画面

Apple の Human Interface Guidelines に沿った作りで、一覧の画面とアプリは同じ部品・並びにしている。色・文字の大きさ・動きの値は `src/shared/theme.js` の1か所にあり、一覧の画面にはビルドが `tokens.css` として書き出す。

- **縦長**（スマートフォン、または縦長の窓）: アプリと同じ。上のバーはなく、画面の移動は下の真ん中のボタン（押すとメニュー）。一覧は大きな見出し、検索（右端のフィルターのアイコンでサイトを絞り込む）、カテゴリのチップと、画像が上に大きいカード。追加は右下の丸い「＋」（メニューのボタンの一段上）。メニューのボタンは送っている間は消える。メニューで「一覧」を選ぶと一覧の最上部へ戻る
- **横長**: 左のサイドバー（カテゴリ、再読み込み、設定）と、カードのメイソンリー。追加は右下の「＋」
- ライトとダークは端末（ブラウザ）の設定に従う。動きを減らす設定では、移動と拡大縮小をやめる
- カードを押すと元のページを開く。本文は5行を超えたら「続きを見る」でその場で開く。「…」（アプリは長押しでも）でカテゴリの変更・元のページ・削除。カテゴリの札でもカテゴリを変えられる
- 色: 選択中などの色（アクセント、既定は抹茶の黄緑）と、その地の上の文字の色（自動・白・黒・自由な色）は「設定」の「外観」で、カテゴリの色は「カテゴリ」の「編集」で色の点を押して選ぶ（決まった11色、カラーサークル・RGB の自由な色、自動）。利用者ごとに保存し、Web とアプリで共通
- `/?add=<URL>` で開くと、その URL で追加のシートを開く（保存は「追加」を押したときだけ）
- iPhone の Safari で共有の「ホーム画面に追加」をすると、アイコンから全画面で開ける（PWA）。ホーム画面のものは Safari と Cookie が別なので、最初に一度ログインする
- アイコン（アプリ・ファビコン・PWA・拡張）は `design/icon/make-icon.jsx` を Illustrator で動かして書き出す。元の絵は `design/icon/twimark-icon.ai`

## 追加のしかた（拡張）

- ツールバーのTwimarkのボタン: 開いているポストや記事を追加する
- 右クリック: ポストや記事のリンクの上で「Twimarkに追加」、ページの上で「このページをTwimarkに追加」。Xのタイムラインでは、ポストの日時のリンクを右クリックする
- 共有メニュー: Xのポストの共有メニュー、noteの記事の共有メニューと記事下の共有の並び、Qiitaの記事の共有の並びにある「Twimarkに追加」

どれもカテゴリ（とサブカテゴリ）を選んで「追加」を押す。本文を取得できなかったときは、出てくる欄に本文を貼り付けて保存する。

## サブカテゴリ

カテゴリの下に1段持てる（例: AI活用 › Claude）。一覧の画面とアプリの「カテゴリ」（横長の一覧の画面ではサイドバー）の「編集」で、「サブカテゴリを追加」で足し、⊖ で消し、右のつまみのドラッグで同じカテゴリの中を並べ替える。

つまみで動かした行がほかのカテゴリの行に半分以上重なったところで離すと、その下に入る。カテゴリはサブカテゴリになり（持っていたサブカテゴリも同じ段に並ぶ）、サブカテゴリはそのカテゴリへ移る。サブカテゴリを動かしている間に出る「ここに置くとカテゴリになります」に置くと、カテゴリに戻る。ブックマークもついて移り、同じ名前があれば1つに合わさる。編集中に名前を押すと、同じことをメニューで選べる。カテゴリを選ぶとサブカテゴリのものも含めて出し、サブカテゴリを選ぶとその中だけを出す。

- カテゴリを消すと、そのブックマークは消えずに「未分類」に出る。サブカテゴリも消える
- サブカテゴリを消すと、そのブックマークはカテゴリの直下に戻る

## iPhoneアプリ

`src/mobile` の Expo のアプリ。App Store には出さず、iPhone の Expo Go で開く。一覧の画面と同じデータで、同じ機能（一覧と絞り込み、カードのカテゴリの変更・削除、カテゴリとサブカテゴリの管理、追加、設定のパスキー・パスワード・トークン・招待・ログインの履歴）を持つ。パスキーの追加は、Web の画面をアプリの中で開いて行う。

この版（アプリのトークン、D1 の `0003`）を公開する前にログインしたアプリは、データの読み書きはそのままできるが、設定を使うにはログインし直す（前のトークンは拡張と同じ扱いで、設定を変えられない）。

### はじめに（一度だけ）

1. iPhone に App Store から Expo Go を入れ、Expo のアカウント（無料）でサインインする。Expo Go は、サインインしたアカウントが持つプロジェクトの更新だけを開く。
2. PC で、同じアカウントで EAS のプロジェクトを作る。

   ```bash
   cd src/mobile
   npm ci
   npx eas-cli login
   npx eas-cli init
   ```

   `init` は `app.json` の `expo.extra.eas.projectId` にプロジェクトIDを入れる（`app.config.js` があるので手で入れるよう言われたら、表示されたIDをそこに入れる）。この変更はコミットする。`updates.url` と `runtimeVersion` は `app.config.js` が作る。
3. https://expo.dev の Account settings → Access tokens でトークンを作り、GitHub のリポジトリの Settings → Secrets and variables → Actions に `EXPO_TOKEN` として入れる。
4. main に push すると `.github/workflows/mobile.yml` が EAS Update の `main` チャンネルへ公開する。Expo Go で `exp://u.expo.dev/<プロジェクトID>?channel-name=main` を開く（Safari のアドレス欄に入れるか、Expo Go の Projects に出るものを開く）。
5. アプリの「設定」で「ブラウザでログイン」を押す。Twimark の画面がアプリの中で開くので、ログイン（パスキーかパスワード）して「渡す」を押す。これが動かないときは、下の「ID とパスワードでログイン」で入る。端末のトークンはこの iPhone のキーチェーンにだけ置かれる。

### Xアプリの共有シートから追加する（ショートカット）

1. アプリの「設定」の「URL をコピー」で、ショートカットに入れる URL をコピーする。EAS Update から開いたアプリでコピーする（開発サーバーから開いたときと URL が違う）。
2. ショートカットアプリで新しいショートカットを作る。
   - 詳細（ⓘ）で「共有シートに表示」をオンにし、受け取るものを「URL」だけにする。名前は「Twimarkに追加」など
   - アクション「URL をエンコード」: 入力は「ショートカットの入力」
   - アクション「テキスト」: コピーした URL を貼り、その直後に「エンコードされたテキスト」をつなぐ
   - アクション「URL を開く」: 入力は「テキスト」
3. X アプリでポストの共有ボタン →「その他の方法でポストを共有」（共有シート）→「Twimarkに追加」。アプリの追加のシートが開くので、カテゴリ（とサブカテゴリ）を選んで「追加」を押す。

X の「リンクをコピー」をしてから、アプリの一覧の「＋」で「クリップボードから貼り付け」でも追加できる。EAS Update の作り直しなどで共有シートから開かなくなったら、1 からやり直す。

### 開発サーバーで試す

```bash
cd src/mobile
npx expo start
```

PC と iPhone を同じネットワークにつなぎ、出てきた QR コードを iPhone のカメラで読む。

## 公開（Cloudflare）

手元のログイン済みの wrangler から公開する（GitHub Actions では公開しない）。初回は D1 の表を作ってから公開する。

```bash
npm ci
npm run db:migrate
npm run deploy
```

`deploy` は自己テスト、ビルド、`wrangler deploy` の順に行い、どれかが失敗したら止まる。wrangler は作業フォルダの `.wrangler/` にアカウント名（メールアドレス）を書くので、コミットしない（`.gitignore` にある）。

パスワードの PBKDF2 の反復回数は `wrangler.jsonc` の `vars.PBKDF2_ITERATIONS`。Free プランの CPU の上限で登録やログインが止まるときは下げる（使った回数は利用者ごとに残るので、あとで変えても前のパスワードで入れる）。

## 開発

```bash
node scripts/self-test.mjs
node scripts/build.mjs
```

```bash
cd src/mobile && npx expo export --platform ios --output-dir ../../build/mobile
```

手元で Worker と画面を動かすときは、`npx wrangler d1 migrations apply twimark --local` のあと `npx wrangler dev`。

依存パッケージは、ルート（Worker の `@simplewebauthn/server` と `wrangler`）と `src/mobile` にだけある。一覧の画面と拡張は依存を持たない。アプリは `src/shared` を写さずに読み込む（`src/mobile/metro.config.js`）。詳しい決まりは `docs/requirements/project-rules.md`、要件は `docs/requirements/current-mvp.md`。
