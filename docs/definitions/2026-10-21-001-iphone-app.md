## 目的

Twimark に iPhone アプリを足し、iPhone でもブックマークの追加と管理ができるようにする。

- アプリは Expo で作り、Expo Go で開く。App Store には出さず、Apple Developer Program（有料）も使わない。
- main への push のたびに GitHub Actions が EAS Update へ公開する。PC で開発サーバーを動かしていなくても、Expo Go からいつでも開ける。
- 追加の入口は、X アプリの共有ボタン（添付1枚目）から開く共有シート（添付2枚目の「その他の方法でポストを共有」で出るものと同じ）に置く iOS のショートカット。ショートカットがポストの URL を付けてアプリを開き、アプリでカテゴリを選んで保存する。
- アプリの機能は一覧の画面（Web）と同じにする。データも同じ `data/bookmarks.json` を使う。
- PC の Web 版 X からの追加は、今の拡張機能（共有メニューの「Twimarkに追加」）のまま変えない。

## 方法

### 共有の処理

- アプリは `src/shared/store.js` と `src/shared/meta.js` をそのまま使う。`metro.config.js` の `watchFolders` に `../shared` を入れて読み込む。写しは作らない。
- React Native の `fetch` には CORS の制限がない。note と Qiita も、拡張と同じく記事の HTML から取得できる。
- Hermes に `atob`・`btoa`・`TextEncoder`・`TextDecoder` があるかを、最初に Expo Go の実機で確かめる。足りないものだけ `App.js` の先頭で補う。補えるのが依存パッケージだけなら、それを `src/mobile` に入れて完了報告に書く。
- GitHub の読み込みが iOS のキャッシュで古いまま返るなら、読み込みの URL に時刻のクエリを付ける。付けたら完了報告に書く。

### アプリ（`src/mobile`）

- 言語は JS（このリポジトリと同じ）。Expo の SDK は、作るときの App Store 版 Expo Go が対応しているものにする。
- 依存パッケージは Expo の標準のものに限る。トークンと前回のカテゴリには `expo-secure-store`、リンクの受け取りには `expo-linking`、貼り付けには `expo-clipboard`、元のページを開くには `expo-web-browser` を使う。画面の切り替えは `App.js` の状態で行い、ナビゲーションのライブラリは入れない。
- **一覧**: Web の一覧と同じ機能にする。
  - カテゴリ（すべて、各カテゴリの件数と色、未分類）を横に並べた絞り込み
  - 検索（Web と同じく NFKC でそろえ、空白区切りの語をすべて含む）とサイトの絞り込み
  - カード: カテゴリ、サイト、画像、タイトル、本文（6行で折りたたみ）、作者、日付、元のページを開く、カテゴリの変更、削除（確認つき）
  - 引っぱって再読み込み
  - 色と検索の処理は `src/site/app.js` から `src/shared` に移して共有してよい。移したら Web 側の読み込みも直す
- **カテゴリの管理**: 追加、↑↓ ボタンでの並べ替え、削除（確認つき）。ドラッグでの並べ替えはしない。
- **追加**: 受け取った URL を `parseUrl` で判定し、`fetchMeta` の結果を下見で出す。カテゴリ（前回選んだもの）を選んで「追加」を押すと `ops.add` で保存する。
  - 対象外の URL と保存済みの URL は、理由を出して追加させない。
  - 取得できなかったときは、拡張と同じく本文を貼り付けて保存できる。
  - URL を受け取らずに開いたときは、URL の欄と「クリップボードから貼り付け」のボタンを出す。X の「リンクをコピー」からも追加できる。
- **設定**:
  - トークンの入力、「接続を確かめる」、「この iPhone から消す」
  - ショートカットに入れる URL（`Linking.createURL('add')` の値）をコピーするボタン
  - Web の一覧を開くリンク
- トークンがなければ一覧を読むだけにし、編集の操作を出さない（Web と同じ）。
- 取得した文字列は `<Text>` でだけ描く。画像とリンクは `https:` のものだけを使う。

### 共有シートからアプリを開く

- アプリが受け取るリンクは `<アプリの URL>/--/add?url=<エンコードしたポストの URL>`。`expo-linking` の `useURL` で受け、アプリが起動済みでも追加の画面に移る。
- Expo Go で EAS Update のアプリを開く URL の形（`exp://u.expo.dev/<プロジェクトID>…`）は、実機で確かめてから README に書く。決め打ちしない。設定の画面に出す値を正とする。
- ショートカットは配布しない。README に作り方を書く。
  1. 「共有シートに表示」をオンにし、受け取るものを URL にする
  2. 「URL をエンコード」で入力をエンコードする
  3. 「URL を開く」で、設定の画面からコピーした URL の後ろに `?url=` とエンコードした値をつないで開く
- X アプリから共有される URL には `?s=…&t=…` が付く。`parseUrl` はクエリを許して保存用の形に直すので、そのまま渡してよい。

### 配信（EAS Update）

- 一度だけ利用者が行うこと（README に書く）:
  1. Expo のアカウントを作る
  2. `src/mobile` で `npx eas-cli login`、`npx eas-cli init`、`npx eas-cli update:configure` を実行する（`app.json` にプロジェクトIDと `updates.url` が入る。これはコミットしてよい）
  3. Expo のアクセストークンを、GitHub のリポジトリの Secrets に `EXPO_TOKEN` として入れる
- `mobile.yml`: `expo/expo-github-action` で `eas update --auto --channel main --non-interactive` を `src/mobile` で実行する。`EXPO_TOKEN` がなければ公開をとばして成功で終える（設定前の push で失敗を出さない）。
- Expo Go で開く URL は README に書く（確かめた形）。
- `pages.yml` は変えない。`src/mobile` の変更でも Pages は配信し直されるが、害はないので許す。

### 定義の外で決めたこと

- **Expo の SDK は 57:** 最新は 58（2026-10-15 公開）だが、App Store 版の Expo Go はまだ 57 まで。`create-expo-app --template blank@sdk-57` で作った。
- **補う機能は要らなかった:** `TextDecoder`・`structuredClone`・`URL` は Expo の実行環境（`expo/src/winter`）が入れ、`atob`・`btoa`・`TextEncoder` は Hermes にある。`structuredClone` の置き換えは定義どおり行った。キャッシュ対策の時刻のクエリは付けていない（実機で古いまま返るかは未確認）。
- **共有の処理を `src/shared/view.js` に移した:** 色の割り当て（`CYCLE`、`toneOf`）と検索（`textMatches`、`searchTextOf`）。`src/site/app.js` もここから読む。
- **依存パッケージを2つ足した:**
  - `react-native-safe-area-context`: RN 0.86 で `SafeAreaView` が非推奨のため
  - `expo-updates`: EAS Update に要る
- **`app.config.js` と `eas.json` を足した:**
  - Expo Go は自分の SDK と同じ runtimeVersion（`exposdk:57.0.0`）の更新だけを開くので、`app.config.js` で `runtimeVersion` を `sdkVersion` の方針にした。
  - `updates.url` は `app.json` のプロジェクトIDから作る。そのため初回の手作業は `eas init` だけになり、定義の `update:configure` はやめた（`runtimeVersion` を `appVersion` に書き換えるおそれがあるため）。
  - `eas.json` には `cli.version` だけを書いた。
- **ショートカットに入れる URL を自分で組み立てた:** `Linking.createURL` は Expo Go のクエリ（`channel-name` など）を渡したクエリの後ろに足す。`queryParams: { url: '' }` では `url=` が最後にならないので、`createURL('add')` の後ろに `?url=` か `&url=` を付けた。

  - 公開の前に `self-test.mjs` を実行する。
  - `eas update` には `--environment production` を付けた（SDK 55 から必須）。
- **ルートの `.gitignore` は変えていない:** `create-expo-app` が作った `src/mobile/.gitignore` が `.expo/`・`node_modules/`・`/ios`・`/android` を外している。

### 差分のレビューで見つけて直したもの

1. **重大: 1分以内に2回目の書き込みをすると失敗する。**
   - 原因: Expo の `fetch` は `cache: 'no-store'` を無視し、iOS の `URLSessionConfiguration.default` を使う（`expo/ios/Fetch/ExpoFetchModule.swift`）。GitHub API は `Cache-Control: public, max-age=60` を返す（`curl` で確認）。そのため、書き込みの前の読み込みが古い sha をキャッシュから返し、409 が4回続いて `conflict` になる。
   - 修正: `src/mobile/github.js` を足し、アプリの読み込み（GET）だけ URL に `t=<時刻>` を付けた。GitHub API は余分なクエリを無視する（`curl` で 200 を確認）。一覧の画面と拡張は変えていない。
   - 完了報告の「キャッシュ対策の時刻のクエリは付けていない」は、この修正で置き換わる。
2. **手で直されたデータで一覧が落ちる。** `normalize` は `id` と `url` があれば残すので、`text` がない1件があるとカードの `b.text.length` が例外になる。本文がないときは空として扱うようにした。削除の確認も `title`・`text`・`url` の順で使う。
3. **選んでいたカテゴリを消すと、一覧が空のままになる。** そのときは「すべて」として扱うようにした。
4. **↑↓ を続けて押すと、並びを上書きしてしまう。** 保存の前の並びから入れ替えた順で上書きしていた。保存の間はカテゴリの操作を止めるようにした。
5. **トークンの保存に失敗しても何も出ない。** キーチェーンへの保存と削除の失敗を画面に出すようにした。
