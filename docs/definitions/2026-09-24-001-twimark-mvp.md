## 目的

PortalのTips（Xのポストをカテゴリ付きのカードで見る機能）と同じ使い勝手のブックマーク一覧を、Portalとは別の単独のツールにする。対象をX・note・Qiitaに広げ、ブラウザ拡張から追加できるようにする。

- 一覧の画面はGitHub Pages（公開リポジトリ `totemonekoze/Twimark`）で配信する。
- ブックマークのデータは別の非公開リポジトリ（既定の名前は `Twimark-data`）のルートにある `bookmarks.json` に置き、GitHub REST APIで読み書きする。サーバーは持たない。
- 画面と拡張は、利用者が自分で発行したfine-grained personal access token（データ用リポジトリだけ、Contentsの読み取りと書き込みだけ）で読み書きする。トークンを入れていないブラウザでは中身は何も見えない。

## 方法

### データ

`bookmarks.json` の形:

```json
{ "version": 1, "categories": ["AI活用", "UIデザイン", "フロントエンド", "Cloudflare", "ツール", "その他"],
  "bookmarks": [
    { "id": "x:<ポストID>", "site": "x", "url": "https://x.com/<handle>/status/<ID>",
      "author": { "name": "", "handle": "" }, "postedAt": "<ISO 8601 か null>", "title": "", "text": "",
      "photos": [{ "url": "" }], "videos": [{ "thumbnail": "" }], "category": "", "savedAt": "<ISO 8601>" } ] }
```

- `id` は `x:<ポストID>`、`note:<記事キー>`、`qiita:<記事ID>`。同じ `id` は1件だけ。
- ファイルがまだないときは、既定のカテゴリ（PortalのTipsと同じ6つ）と空の一覧として扱い、最初の書き込みで作る。
- 書き込みは毎回「最新を読む→操作を当てる→`sha` を付けてPUT」。PUTが409か422（ほかから先に書かれた）なら読み直して当て直す。4回まで。1回の書き込みが1コミットになる。
- 1MBを超えてContents APIが本文を返さないときは、Git Blobs APIで読む。
- GitHub APIへの要求は `cache: 'no-store'` で送る（ブラウザのキャッシュで古い `sha` を読まないため）。
- 失敗は画面が出せる文言にする。401はトークンが無効、403は権限不足（残り回数が0なら回数制限）、404はリポジトリが見つからない、通信失敗は接続できない。

### URLの判定と本文の取得（拡張の `meta.js`）

| サイト | 受け付けるURL | 保存するURL | 取得 |
|---|---|---|---|
| X | `https://(x\|twitter\|mobile.twitter).com/<handle>/status/<数字>`（後ろの `/photo/1`、クエリは無視）、`/i/web/status/<数字>` | `https://x.com/<handle>/status/<数字>` | `https://api.fxtwitter.com/<handle>/status/<数字>`。取り出す項目はPortalの `extractTweet` と同じ（作者、投稿日時、本文、画像、動画のサムネイル） |
| note | `https://note.com/<ユーザー>/n/<n+英数字>` | 同じ形（クエリを除く） | 記事のHTMLを取得し、JSON-LDの `headline`・`datePublished`・`author.name` とOGPの `og:description`・`og:image` を取り出す |
| Qiita | `https://qiita.com/<ユーザー>/items/<20桁の16進>` | 同じ形 | noteと同じ |

- HTMLの解析は正規表現で `<meta>` と `<script type="application/ld+json">` だけを読む（Service WorkerとNodeでも動き、テストできるように）。
- 取得できなかったときは、PortalのTipsと同じく、本文を貼り付ける欄を出して保存できるようにする。
- 要約は持たない。

### 拡張機能（Manifest V3、Chrome/Edge共通）

追加の入口は3つで、どれも同じ「追加の画面」（`popup.html`）を開く。

1. ツールバーのボタン: 開いているタブのURLで追加の画面をポップアップとして開く。
2. 右クリック: 対象のURLのリンクの上で「Twimarkに追加」、対象のページの上で「このページをTwimarkに追加」。追加の画面を小さなウィンドウで開く。
3. 共有メニューへの差し込み（`content.js`）: 次の場所に「Twimarkに追加」を足す。押すと小さなウィンドウで追加の画面を開く。
   - X: ポストの共有ボタン（`button[data-engagement-action="share"]`。古い画面では `aria-label` が「共有」「Share」で始まる `aria-haspopup="menu"` のボタン）で開いた `[role="menu"]` に、既存の項目を複製した項目を足す。対象のポストは、共有ボタンから祖先をたどって最初に見つかる `/<handle>/status/<数字>` のリンク。
   - note: 記事の共有メニュー（`[role="menu"]` の `id` が `shareMenu` で始まるもの）と、記事下の共有の並び（`.o-shareBooster__share`）。
   - Qiita: 記事の共有の並び（「Facebookでシェア」のボタンを持つ並び。左の縦の並びと記事下の並び）。
   - 差し込む項目は、そのサイトの既存の項目を複製し、ラベルとアイコンだけを変える（見た目を合わせるため）。サイトの画面が変わって見つからないときは、何も足さない（サイトの動作は変えない）。

追加の画面:
- 設定（データ用リポジトリの所有者・名前、トークン）がなければ、設定画面へのリンクだけを出す。
- URLが対象外なら、その旨を出す。
- データを読み、保存済みなら「保存済み」と出して追加させない。
- 本文・記事の情報を取得して、タイトルか本文の冒頭を出す。
- カテゴリは `bookmarks.json` の一覧から選ぶ。前回選んだカテゴリを最初から選んでおく。
- 追加できたら「追加しました」と出し、ウィンドウで開いたときは少し待って閉じる。

設定画面（`options.html`）: 所有者、リポジトリ名、トークンを `chrome.storage.local` に保存する。「接続を確かめる」で読み込めるかと件数を出す。

権限: `activeTab`、`contextMenus`、`storage`。ホスト権限は `api.github.com`、`api.fxtwitter.com`、`note.com`、`qiita.com`。コンテンツスクリプトは `x.com`、`twitter.com`、`note.com`、`qiita.com`。

### 一覧の画面（GitHub Pages）

PortalのTipsの画面を、ビルドの要らない素のHTML・JS・CSSに移す。配色と部品はPortal（白を一段落とした地、くすみパステルの緑、カテゴリの色の割り当て）に合わせる。ダークモードは持たない（Portalと同じ）。

- サイドメニュー: すべて、カテゴリ（件数、色、並べ替えのつまみ、×で削除）、一覧にないカテゴリのものをまとめた「未分類」、「＋ カテゴリを追加」。並べ替えはドラッグと、つまみを選んで ↑↓ キー。狭い画面では本文の上の折りたたみ。
- 本文: 検索欄（全角・半角をそろえ、空白区切りの語をすべて含むもの）、サイトの絞り込み（すべて・X・note・Qiita）、メイソンリーのカード。
- カード: カテゴリの札とサイト名、画像、タイトル（記事）、本文（6行を超えたら「続きを読む」）、作者と日付、「元のページを開く」、カテゴリの変更、削除（確認あり）。
- 絞り込みと検索はURLのクエリ（`category`、`uncategorized`、`site`、`q`）に残す。
- 右上の「設定」で所有者、リポジトリ名、トークンを入れる。このブラウザの `localStorage` にだけ保存し、「このブラウザから消す」で消せる。
- 画面から追加はしない（追加は拡張から）。
- 書き込みは1件ずつ順番に送る。成功したら返ってきた最新のデータで描き直し、失敗したら元に戻して理由を出す。
- `Content-Security-Policy` を `<meta>` で付け、読み書き先を `api.github.com` だけにする。画像は `https:` だけ。外部のスクリプトとフォントは読まない。取得した文字列は `textContent` でだけ描く。

### ビルドと配信

- `node scripts/build.mjs` で `build/site` と `build/extension` を作る。依存パッケージは持たない。
- 拡張は `build/extension` を「パッケージ化されていない拡張機能を読み込む」で入れる。
- GitHub Pagesは、Actionsのワークフローでビルドして `build/site` を配信する。リポジトリの Settings → Pages の Source を「GitHub Actions」にするのは利用者の操作。
- `build/` と `release/` はGitで追跡しない。

## 範囲外

- 画面からのURLでの追加（noteとQiitaのHTMLはブラウザからは取得できない。`docs/backlog.md` に書く）
- 要約、PortalのTipsからのデータ移行、Portalの変更
- 拡張のアイコン画像（ブラウザの既定の表示を使う）、ストアへの公開、zipの作成
- noteの独自ドメインの記事、Xのポスト以外（プロフィール、リスト）
- リポジトリの作成、トークンの発行、Pagesの設定、コミットとプッシュ（利用者が行う。今回の指示にない）

## 受け入れ条件

1. `node scripts/self-test.mjs` がすべて成功する。少なくとも次を確かめる。
   - X・note・Qiitaの受け付けるURLの形と、保存するURL・`id`。対象外のURL（`x.com/home`、Qiitaのタグのページなど）を受け付けない。
   - fxtwitterの応答からの項目の取り出し、noteとQiitaの形のHTMLからの記事の情報の取り出し（文字参照の復元を含む）。
   - GitHubの読み書き: ファイルがないときは既定のデータになる、最初の書き込みでファイルを作る、2回目以降は `sha` を付ける、409のあと読み直して成功する、日本語と絵文字が壊れない、Contentsが本文を返さないときはBlobで読む、401・403・404の文言。
   - 一覧の操作: 重複の追加を拒む、一覧にないカテゴリでの追加を拒む、カテゴリの追加（重複、20文字、30個）、削除、並べ替えの検証、1件のカテゴリの変更。
2. `node scripts/build.mjs` のあと、`build/site` と `build/extension` の全JSが `node --check` を通る。`build/extension/manifest.json` がJSONとして読める。
3. 拡張の差し込みの処理を、X・note・Qiitaの実際のページに流し込み、共有メニュー・共有の並びに「Twimarkに追加」が出ることと、Xでは対象のポストのURLが取れることを確かめる。
4. 公開リポジトリに入るファイルにトークンと個人のデータを含まない。

### 定義の外で決めたこと

- `src/extension/popup.css` と、ルートの `package.json`（`"type": "module"` と `build`・`test` のスクリプトだけ）を足した。対象ファイルの表にはない。
- `content.js` のまとめて調べる処理は `requestAnimationFrame` ではなく `setTimeout`（80ms）にした。描画されていないタブでは `requestAnimationFrame` が止まり、ブラウザペインで差し込みが起きなかったため。
- メニューを閉じる処理: X はフォーカスのある要素への Escape で閉じる。note は Escape では閉じないため、まだ開いていれば共有ボタンをもう一度押す。
- 差し込むアイコンは、`svg` か `img` があればそれを、なければ `<i>`（noteの共有の並びはCSSで絵を出している）を差し替える。
- Pagesのワークフローは、ビルドの前に自己テストも走らせる。
- 一覧で、絞り込みの結果が0件のとき、ブックマークが1件でもあれば「一致するブックマークはありません」を出す（PortalのTipsは検索語がないと「まだありません」を出していた）。

### 確かめていないこと

- 拡張機能を実際にChrome/Edgeへ読み込んでの動作（ポップアップ、右クリックのメニュー、設定画面、`chrome.windows.create` で開く小さなウィンドウ、本物のGitHub APIへの書き込み）。この環境の内蔵ブラウザには拡張を読み込めない。
- ログインしたXの画面での共有メニュー（確かめたのはログインしていない表示。古い画面向けの `aria-label` の判定は実物で確かめていない）。
- X の共有メニューに足した項目の見た目（ホバーの色は `content.css` で付けた）。
- GitHub Pagesへの配信（ワークフローは未実行）。
