# Twimark：Apple の HIG に沿った画面の刷新と、Web とアプリの機能をそろえる

- 定義日: 2026-10-22
- 状態: reviewed
- 定義: Claude Code（2026-10-22）
  - 指示: 「webアプリケーション版・iOSアプリ版のUI/UXデザインを、Appleヒューマンインターフェースデザイン（https://developer.apple.com/jp/design/human-interface-guidelines）を参考に、直感的かつ動的な仕上がりに刷新いただけますか？ webアプリケーション版のスマートフォン接続時、またはブラウザウィンドウ縦長表示のときとアプリ版のデザインは共通するように調整ください。webアプリケーション版とアプリ版で持っている機能も同等にすること。まずは定義から。」
  - その後の回答: 外観は「端末の設定に従う」（ライトとダーク）。配色は「iOS 標準を踏襲し、Portal っぽいくすみカラーもアクセントに使用」。アプリの設定は「アプリのトークンだけ許す」。Web の追加は「Worker が代わりに取得する」。

## 目的

- **HIG に沿った見た目と操作:** 一覧の画面（Web）と iPhone アプリを、Apple の Human Interface Guidelines の作り（大きな見出し、タブバー、シート、検索欄、セグメント、コンテキストメニュー、編集モード、Dynamic Type、44pt の押せる大きさ、ダークモード）に寄せ、触って分かる・動きで状態が伝わる画面にする。
- **縦長の Web とアプリを同じ形に:** Web をスマートフォンで開いたとき、またはブラウザの窓が縦長のときは、アプリと同じ画面の組み立て（下のタブバー、同じ見出し・部品・並び）にする。横長の広い窓では、サイドバーの画面にする（iPad・Mac の作り）。
- **機能をそろえる:** 今は Web にだけある「設定」の操作（パスキー、パスワードの変更、端末のトークン、招待、ログインの履歴）をアプリにも、アプリにだけある「追加」を Web にも持たせる。

## 前提

- 定義 001〜004 はすべて実装・公開済み（`b45ac01`）。
- アプリは App Store 版の Expo Go（SDK 57）で動かす。Expo Go に入っていないネイティブのモジュールは使えない。足す依存は `npx expo install` で入れる、Expo Go に入っているものだけにする。
- 一覧の画面は依存パッケージを持たない（素の HTML・JS・CSS）。これは変えない。
- CSP は `default-src 'self'`。外部のフォント・アイコン・スクリプトは読まない。

## 機能の対応表（実装のあと）

| 機能 | Web | アプリ | 今との違い |

| 一覧（カテゴリ・サブカテゴリ・未分類の絞り込み、件数と色、サイトの絞り込み、検索） | ○ | ○ | 変わらない |

## 方法

### デザインの決まり（Web とアプリで共通）

- **値の正本は `src/shared/theme.js` の1か所。** 色は `{ light, dark }` の組で持つ。
  - アプリ: `useColorScheme()` で選ぶ。
  - Web: `build.mjs` が `:root { --label: light-dark(<light>, <dark>); … }` の形の `tokens.css` を書き出し、`style.css` はその変数だけを使う。`color-scheme: light dark`。
- **色（iOS 標準を踏襲）:**
  - 地・面・文字・区切りは iOS のシステムの色に合わせる。地 `systemGroupedBackground`（#F2F2F7 / #000000）、面 `secondarySystemGroupedBackground`（#FFFFFF / #1C1C1E）、一段上の面 `tertiarySystemGroupedBackground`（#F2F2F7 / #2C2C2E）、文字 `label`、薄い文字 `secondaryLabel`・`tertiaryLabel`、区切り `separator`、入力欄の地 `tertiarySystemFill`。
  - 削除などは `systemRed`（#FF3B30 / #FF453A）。
  - **アクセント（tint）は Portal のくすみ緑**: ライト #347255、ダークは同じ色相で明るくしたもの（#7FB89B を基準に、ダークの面の上で文字のコントラスト 4.5:1 以上になる値）。選んだタブ、ボタン、リンク、選んだチップ、スイッチに使う。
  - **カテゴリの11色はくすみパステルのまま**（`view.js` の割り当ては変えない）。ダーク用に、地は暗く・文字は明るくした組を作る。どの組も文字と地のコントラストは 4.5:1 以上。
- **文字:** システムのフォント（Web は `-apple-system, BlinkMacSystemFont, system-ui, 'Hiragino Sans', 'Noto Sans JP', sans-serif`）。大きさは iOS のテキストスタイルに合わせる（Large Title 34、Title 2 22、Title 3 20、Headline 17 太字、Body 17、Callout 16、Subheadline 15、Footnote 13、Caption 12）。
  - アプリは Dynamic Type に従う（`allowFontScaling` を切らない。並びが崩れないよう、文字が大きくなっても折り返す作りにする）。
  - Web の縦長は Body 17px、横長は 15px を基準にする。
- **形:** 面の角丸はカード 14、シートの上の角 12、ボタン・入力欄 10、チップは丸。カードに枠線は付けず、ライトでは薄い影、ダークでは面の色の段で分ける。押せるものはすべて 44×44 以上。
- **アイコン:**
  - アプリは SF Symbols（`expo-symbols`）。
  - Web は SF Symbols を使えない（Apple のライセンスが Apple の環境の外での使用を認めない）ので、形の近い SVG を `src/site/icons.js` に置く。ISC ライセンスの Lucide から要るものだけを写し、ライセンスの表示を付ける。
  - 使うもの: 一覧（`books.vertical`）、カテゴリ（`folder`）、設定（`gearshape`）、追加（`plus`）、検索、その他（`ellipsis`）、削除（`trash`）、元のページ（`arrow.up.right.square`）、並べ替えのつまみ（`line.3.horizontal`）、選択（`checkmark`）、閉じる（`xmark`）、貼り付け（`doc.on.clipboard`）、パスキー（`person.badge.key`）、招待（`person.badge.plus`）、履歴（`clock`）、再読み込み（`arrow.clockwise`）。

### 画面の組み立て

#### 縦長（Web の `(max-width: 767px), (orientation: portrait)`、とアプリ）

Web とアプリで、次の並び・名前・部品を同じにする。

- **下のタブバー:** 「一覧」「カテゴリ」「設定」の3つ（アイコンと名前）。半透明の素材（アプリは `expo-blur` の `BlurView`、Web は `backdrop-filter: blur() saturate()`）。下の安全領域を空ける（Web は `viewport-fit=cover` と `env(safe-area-inset-*)`）。
  - 追加はタブにしない（HIG ではタブは移動のためのもの）。一覧の右上の「＋」から開くシートにする。
- **見出し:** 各タブの上に大きな見出し（Large Title：「一覧」の見出しは選んでいる絞り込みの名前、「カテゴリ」「設定」）。下へ送ると、上の細いバーの中央の小さな見出しに縮む。バーも半透明の素材。
- **一覧:**
  - 見出しの下に検索欄（iOS の検索欄の形。虫めがね、消すボタン、「キャンセル」）。
  - その下に、カテゴリのチップを横に送る並び（すべて・各カテゴリ・未分類、件数と色）。カテゴリを選ぶと、その下にサブカテゴリのチップの並びが出る（「〇〇のすべて」と各サブカテゴリ）。
  - サイトの絞り込みはセグメント（すべて・X・note・Qiita）。
  - カードは1列（窓が 600px 以上の縦長なら2列）。
  - 右上に「＋」（追加）。Web はその左に「…」（再読み込み）。
- **カード:**
  - 上から、画像（ある時だけ、16:9、角丸の中に収める）、カテゴリの札（`カテゴリ › サブカテゴリ`）とサイト、タイトル、本文（6行で折りたたみ、「続きを読む」）、作者と日付。
  - カードを押すと元のページを開く（アプリはアプリ内のブラウザ、Web は新しいタブ）。
  - 右上の「…」で、カテゴリの変更、元のページを開く、削除（赤）のメニューを出す。アプリは長押しでも同じメニューを出す。
  - カテゴリの札を押すと、カテゴリの変更を開く。
- **カテゴリの変更:** 下からのシート。カテゴリと、その下に字下げしたサブカテゴリの一覧で、今のものにチェック。選ぶと保存して閉じる。
- **削除の確認:** アクションシート（「削除」赤、「キャンセル」）。対象の名前を出す。
- **追加のシート:**
  - URL の欄（開いた時に入力の状態にする）、「クリップボードから貼り付け」。
  - 下見のカード（取得中は読み込みの表示）。取得できなかったときは本文の欄。
  - カテゴリのチップ、サブカテゴリのチップ（なし・各サブカテゴリ）。前回の組を選んでおく。
  - 右上に「追加」、左上に「キャンセル」。保存済みならその旨を出し、「追加」を押せなくする。
  - 追加できたら閉じ、一覧の先頭にそのカードを動きで入れる。
- **カテゴリのタブ:**
  - iOS のグループ表示のリスト。カテゴリの行（色の点、名前、件数、›）と、その下に字下げしたサブカテゴリの行。行を押すと、そのカテゴリで絞った一覧へ移る。
  - 右上の「編集」で編集モードにする。行の左に削除の「⊖」、右に並べ替えのつまみを出し、つまみのドラッグで並べ替える（サブカテゴリは同じカテゴリの中だけ）。
  - 編集モードでは、各カテゴリの下に「＋ サブカテゴリを追加」、リストの下に「＋ カテゴリを追加」を出す。追加は名前を入れる小さなシート（アプリは `Alert.prompt`）。
  - 並べ替えは、読み上げ（VoiceOver）では「上へ」「下へ」の操作でもできる。
- **設定のタブ:** iOS のグループ表示のリスト。次の段の順に出す。
  1. アカウント（ログイン中の ID）
  2. パスキー（一覧、左へのスワイプか「編集」で削除、「パスキーを追加」）
  3. パスワードの変更（押すとシート）
  4. 拡張のトークン（一覧と取り消し、「発行する」で名前を入れるシート、値は一度だけ出してコピー）
  5. 招待（管理者だけ）
  6. ログインの履歴（押すと、30日分を1件1行のリストで出す画面へ。失敗は赤と理由。行を押すと IP・国・端末の元の文字列）
  7. その場所にしかないもの（Web: なし。アプリ: ショートカットの URL、接続の確認、Web の一覧を開く）
  8. ログアウト（赤）
- **空・読み込み・失敗:** 空のときは、アイコン、見出し、説明、「追加」のボタンを画面の中ほどに出す（iOS の Content Unavailable の形）。読み込み中は回るしるし。失敗は説明と「再読み込み」。

#### 横長（Web の上の条件に当たらないとき）

- **左のサイドバー:**
  - 今と同じ働き（すべて、カテゴリとサブカテゴリの件数と色、未分類、ドラッグと ↑↓ キーでの並べ替え、追加、削除）を、iPad・Mac のサイドバーの見た目にする。
  - 下に「設定」。
- **右:** 上のツールバー（見出し、検索欄、サイトのセグメント、「＋ 追加」、再読み込み）と、メイソンリーのカード（今と同じ列の数）。
- **シート:** カードのメニュー・追加・カテゴリの変更・設定は、縦長と同じ中身を画面の中央のシート（`<dialog>`）で出す。
- **共通にする範囲:** 縦長と横長で、部品（カード、チップ、セグメント、シート、リスト、ボタン）は同じものを使い、組み立てだけを替える。

#### URL（Web）

- 今の `?category=&sub=` と検索語に加えて、縦長のタブを `?tab=categories|settings`（一覧は付けない）、ログインの履歴の画面を `?tab=settings&page=history` で URL に残す。戻るボタンで前の画面へ戻る。
- `/?add=<URL>` で開くと、ログインのあとに追加のシートをその URL で開く。保存は利用者が「追加」を押したときだけ。

### 動き

- **押したとき:** 押せるものは、押している間だけ少し縮める（0.97）か色を濃くする。
- **画面の移り変わり:**
  - シートは下からせり上がり、下へのスワイプで閉じる。アプリは React Native の `Modal`（`presentationStyle="pageSheet"`）、Web は `<dialog>` を下から出す動き。
  - タブは切り替えのときに重ねて入れ替える。
  - 見出しは送りに合わせて縮む。
  - Web で画面の内容が変わるとき（絞り込み、追加、削除、カテゴリの変更）は、使えるブラウザでは View Transitions（`document.startViewTransition`）でカードを動かして並べ直す。使えなければ今の `rise` の動きにする。
  - アプリは `LayoutAnimation` で並びの変化を動かす。
- **ばねの動き:** ばね（減衰があり、行き過ぎの小さいもの）の時間と曲線を `theme.js` に置く。Web は近い `cubic-bezier` にする。
- **触覚（アプリだけ）:** `expo-haptics` で、チップ・セグメントの選択（selection）、追加できた（success）、削除（warning）、並べ替えで持ち上げたとき（impact light）。
- **動きを減らす設定:** Web の `prefers-reduced-motion`、アプリの `AccessibilityInfo.isReduceMotionEnabled` では、移動と拡大縮小をやめて、色と透明度の変化だけにする。

### アプリのトークン（アプリから設定を操作する）

- **`0003`:** `sessions` に `app INTEGER NOT NULL DEFAULT 0` を足す。
- **作るときに `app = 1` にするもの:**
  - アプリへの受け渡し（`?app=` から作るトークン）。受け渡しの画面は `POST /api/tokens` に `{ device, app: true }` を送る。
  - `/api/login/password` の `device` 付きのログイン。
  - 一覧の「設定」で発行するトークン（拡張用）は `app = 0`。
- **今あるアプリのトークン（`app = 0`）:** データの読み書きは今まで通りできる。設定の操作は `web_only` で断られるので、アプリはその時に「設定を使うには、ログインし直してください」と出してログインへ案内する。
- **Worker:**
  - `webOnly()` を「web のセッションか、`app = 1` のトークン」で通す形に替える（名前も替える）。対象はパスワードの変更、パスキーの一覧と削除、端末のトークン、招待、ログインの履歴。
  - パスキーの登録（`/api/passkeys/options`、`POST /api/passkeys`）は、WebAuthn がそのオリジンのブラウザでしか動かないので、web のセッションだけのままにする。
  - 拡張のトークンは今と同じく、どれもできない。
- **端末のトークンの一覧:** `app` を返し、画面では「アプリ」「拡張」と分けて出す。
- **アプリのパスワードの変更:** 変えると今のアプリのトークンも消える（今の決まり）ので、成功したらログアウトの扱いにして、ログインし直してもらう。
- **アプリのパスキーの追加:** `openAuthSessionAsync` で `<PUBLIC_URL>/?tab=settings&passkey=add&app=<戻り先>` を開く。
  - Web でログイン（済みならそのまま）したあと、パスキーの追加を始め、終わったら戻り先へ移る（トークンは渡さない）。
  - アプリは戻ってきたらパスキーの一覧を読み直す。
  - 戻り先は今の `isAppRedirect` で確かめる。

### Web の追加と `/api/meta`

- **`POST /api/meta { url }`:**
  - ログインした人だけ（web のセッション、どの端末のトークンでも）。
  - `parseUrl` が受けない URL は `unsupported_url` で断る。取得先は `meta.js` の決まった URL（fxtwitter、`note.com`、`qiita.com`）だけなので、ほかのホストへは出ない。
  - Worker の `fetch` で `fetchMeta` を呼び、`{ item }`（取得できなければ `item: null`）を返す。
  - 1回の取得は 8 秒で打ち切る。応答の本文は 2MB までだけ読む。
- **使う側:** Web とアプリの追加はこれを使う（アプリの今の直接の取得はやめ、取り方を1つにする）。拡張は今のまま自分で取得する。
- **取得できないとき:** note・Qiita が Worker からの取得を断ったときも、`item: null` になり、今と同じく本文の貼り付けで保存できる。
- **Web の追加の画面:**
  - 中身はアプリの「追加」と同じ。
  - クリップボードは `navigator.clipboard.readText()` で読む（読めないときは欄に貼り付けてもらう）。
  - 前回の組は `localStorage` に置く（読めなくても動く）。

### アプリの作りの方針

- **画面の切り替え:**
  - 今の作り（`App.js` の状態で切り替え）を保ち、移動のライブラリは足さない。
  - 「設定」の中の下の画面（ログインの履歴など）は、その画面の中の状態で出し、左上に「‹ 設定」の戻るボタンを付ける。端から右へのスワイプでも戻る。
- **カテゴリの並べ替え:**
